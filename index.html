What is a REST API?

Run Live Simulator

REST API explained simply

Imagine going to a restaurant. You are the customer, and the kitchen prepares your food. However, you can't go straight to the kitchen to grab your meal.

The Restaurant Metaphor:
You (the Client) place an order (the Request) through the Waiter (the API). The waiter takes your request to the Kitchen (the Server), and brings the food (the Response) right back to your table.

In software, a REST API is that digital waiter. It allows two independent applications (like an Instagram Mobile App and an Instagram Database Server) to talk to each other securely over the web using standard operations.

Why do we actually need APIs?

Without APIs, every single frontend application would have to connect directly to databases, replicate complex security logic, and manage core business logic separately.

Write Once, Serve All

Your backend business code resides securely in a single Spring Boot application, serving iOS, Android, and Web frontends equally.

Data Security

Clients never touch database credentials directly. The REST API acts as a secure firewall validating permissions and incoming data formats.

Real-World API Integration

Swiggy API

When you place an order, your app sends a POST /orders API request with your food basket. The server processes payment and notifies the restaurant.

Instagram API

When you scroll, your app pulls feeds via GET /feed?userId=99. The REST API retrieves posts, formats pictures, and returns them as lightweight data packets.

Amazon Search API

As you search, the website hits GET /products?query=laptop. The database filters millions of rows, returning prices, reviews, and stock limits in milliseconds.

CartController.java 
@RestController
public class CartController {

    // 1. GET Request: Read cart contents
    @GetMapping("/cart")
    public Cart getCart() {
        return cartService.getUserCart();
    }

    // 2. POST Request: Add dynamic item into database
    @PostMapping("/cart/add")
    public String addToCart(@RequestBody Item newItem) {
        cartService.addItem(newItem);
        return "Item successfully added to your cart!";
    }
}

Dynamic Mapping: @PathVariable

Hardcoded URLs are useless. You don't want a separate endpoint for every single product on Amazon! Instead, we map dynamic values inside our URLs.

URL Breakdown Example:

https://api.amazon.com / products / {productId}
Standard Route
Dynamic Variable (Binds to code)
How it connects to code:
The placeholder {productId} in the @GetMapping URL matches the @PathVariable variable name inside the Java method argument list. Spring automatically intercepts the actual value (e.g. 4829) and hands it to your Java code.
ProductController.java 
@RestController
public class ProductController {

    // Client visits: GET /products/8854
    @GetMapping("/products/{id}")
    public Product getProductDetails(
        @PathVariable("id") int productId
    ) {
        // Spring automatically assigns 8854 to 'productId'
        return productDb.findProductById(productId);
    }
}

API Communication: JSON Response

Computers don't exchange Java Class source files. They exchange structured strings of data. The standard global medium is JSON (JavaScript Object Notation).

Jackson: The Translator

Spring Boot packages a critical library called Jackson. When your Java method returns a plain Java Object (like an Instagram Post object), Jackson instantly translates (serializes) its private fields into standard JSON format. You do not write JSON strings by hand!

Interview Q&A Prep Desk

Ace your next technical interview. Click on any question card below to reveal the concise, developer-centric answer with real-world context.

Pro-Tip for Interviews:
When asked about REST, always explain using a client-server metaphor first. Explain `@RestController` by highlighting that it bypasses standard HTML rendering and directly serializes JSON using Jackson.

A standard @Controller is used in traditional web apps to return HTML views (like Thymeleaf, JSP). You must add @ResponseBody to make it write JSON directly.

@RestController is a convenient wrapper that combines @Controller and @ResponseBody automatically, telling Spring that every method inside the class directly outputs JSON serialized body data.

@PathVariable extracts values directly from the main URL structure itself. (e.g., /products/{id} -> /products/402). It represents resource hierarchies.

@RequestParam extracts query parameters appending the URL path (e.g., /products?category=shoes). It represents sorting, filtering, or optional search parameters.

Spring Boot automatically registers the Jackson Converter (MappingJackson2HttpMessageConverter). Whenever an endpoint class is declared with @RestController, this Jackson mapper intercepts the returned Java object and maps public properties/getters into standard JSON strings.

Unlike GET requests, data for POST requests arrives inside the invisible HTTP Request Body (usually as raw JSON). The @RequestBody annotation directs Spring to capture this raw JSON text, pass it to Jackson, and convert it instantly into a matching Java Object.

  • 200 OK: Request succeeded, returns requested data.
  • 201 Created: Successfully created a new resource (e.g. POST order).
  • 400 Bad Request: Client sent invalid or malformed data.
  • 404 Not Found: The requested resource could not be found (e.g., product doesn't exist).
  • 500 Internal Server Error: The Spring Boot server crashed due to an unhandled backend exception.
